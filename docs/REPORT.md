# DWG→DXF 端末内変換 試作 — 検証報告（2026-10-25）

## 1. 結論（現時点）

- LibreDWG 0.14（公式リリース）を自前でWebAssembly化し、**DWG読込 → DXF書出 → 出力の自動照合**まで動く試作を作成した。
- 開発環境（Windows / Node・Chromium）では、WASM版の出力は**公式Windows版 dwg2dxf.exe と同一バイト**（試験8ファイル全て。LibreDWGのバグ1件を修正した上で）。WASM化による品質低下は確認されていない。
- 一方、**LibreDWG自体の対応範囲による欠落は実在する**（未対応図形・スタイル類・寸法の関連付け・R13より前の形式など）。アプリはこれを検出し、該当時は「変換成功」と表示しない。
- **実際の業務DWG、AutoCADでの開き直し、iPhone/iPad Safari実機は未検証**。ここから先は実ファイルと実機が必要。

## 2. 既存WASM版の調査とエンジン選定

| 候補 | DWG読込 | DXF書出 | 評価 |
|---|---|---|---|
| `@mlightcad/libredwg-web` 0.8.2 (npm) | ○ | **×** | `--disable-write` でビルド（READMEに明記）。DXF書出は含まれない。ビューア向け |
| `dwg2dxf-converter` 1.0.4 (npm) | ○ | ○ | 事前ビルド済みWASM＋独自関数 `convert_dwg_to_dxf`。ビルドスクリプトとCソースがパッケージに含まれず再現不能。「GPLは感染しない」というREADMEの記述は根拠として採用できない |
| **LibreDWG 0.14 公式tarballから自前ビルド**（採用） | ○ | ○ | 出所・改変内容・ビルド手順を自分で管理できる。公式Windowsバイナリと出力を突き合わせられる |

DXF書出API: `dwg_read_file()` → `dwg_write_dxf(Bit_Chain*, Dwg_Data*)`（`programs/dwg2dxf.c` と同じ呼び出し）。DWG書込（encode）とJSONは不要なので外した。成果物は wasm 約6.0MB + JS 61KB。

## 3. 実装したもの

- `engine/wasm_dwg2dxf.c`: 変換に加えて「DWGから何を読めたか」をJSONで出力（タイプ別件数、クラスの安定度、レイヤー名、ブロック・外部参照、画像参照、文字列と属性タグ、単位・範囲）。
- `web/worker.js`: Web Workerで変換。**変換ごとにWorkerを作り直し、終了時に破棄**してWASMメモリを確実に解放（WASMメモリは縮まないため）。入出力は転送（transfer）でコピーを減らす。
- `web/analyze.js`: 出力DXFをバイト列のまま読み直し、DWG側と照合して判定する。
  - 判定: `完了（自動チェックで差異なし）` / `完了（警告あり）` / `情報が欠落している可能性` / `変換できませんでした`
  - 検出項目: 図形タイプ別件数の減少、LibreDWG未対応・不安定クラス、出力されなかった非図形オブジェクト（スタイル・関連付け等）、テーブル件数、**文字列と属性タグの完全一致**、参照先のない参照（dangling handle）、外部参照・画像参照、DXF構造（EOF・必須セクション）、LibreDWGログのエラー・警告
- `web/sw.js` + `manifest.webmanifest`: PWA。アプリとエンジンを版付きキャッシュに保存し、オフライン起動。自オリジン以外へは接続しない（CSP `connect-src 'self'`）。
- 保存: `<a download>`（Blob）。共有: Web Share API（`navigator.canShare` で対応時のみ表示）。

## 5. 見つかった問題

1. **LibreDWGのバグ（修正済み・パッチ同梱）**: `out_dxf.c` の `cquote()` が文字列終端を書かず、改行を含む文字列（例: 公差記入）の後ろに未初期化メモリが混入。ネイティブ版では偶然ゼロで表面化せず、WASM版ではゴミ文字が出ていた。`engine/patches/0001-*.patch` で修正。上流へ報告する価値あり。
2. **別バージョンへのDXF出力（`--as`）は使えない**: R2018→R2000で図形262→32、R2000→R2018では不完全なDXF。ネイティブ版も同一結果なのでLibreDWG側の問題。→ **出力DXFは元DWGと同じバージョンに固定**し、UIから選択肢を削除した。
3. **出力されない要素（LibreDWG 0.14 の仕様）**:
   - 未対応・未知の図形（例: `ARC_DIMENSION`、UNKNOWN_ENT）は出力されない
   - `MATERIAL`、`MLEADERSTYLE`、`TABLESTYLE`（R2010以降）、`DIMASSOC`（寸法の関連付け）、ダイナミックブロックの評価グラフ等が出力されない → **辞書内に参照先のない参照が残る**（試験141件中126件）。ezdxfは自動修復で読めたが、AutoCADの反応は未確認
   - R13より前（R1.4〜R12）のDWGは試験した全ファイルで欠落を検出
   - R14以前のDXFではR2000以降の図形（MULTILEADER、WIPEOUT等）が出力されない
   - `MLINE` はLibreDWGのソース注記に「AutoCADでの読込に問題」とある
4. **文字コード変換**: Emscripten の iconv は `//TRANSLIT//IGNORE` を受け付けず、LibreDWG内蔵の変換表にフォールバックする。同一バージョン出力では出力に影響なし（ネイティブ版と一致）。
5. 合成DWGの作成に使ったLibreDWGのDWG書込（dxf2dwg）自体に欠陥（属性タグ消失、R2004出力の破損）があり、合成ファイルは「読込側」の確認には限定的にしか使えない。**AutoCAD等で作られた実DWGでの確認が必須**。

## 7. 提出をお願いしたいもの

実際に使うDWGを、可能なら次の観点で数点（社外秘の場合はその旨を明記）:

1. 日本語の文字・寸法・ハッチング・ブロック属性を含む図面（AutoCAD 2018形式 と 2013以前の形式の両方があると良い）
2. 外部参照・画像参照・プロキシ（Civil 3D等）を含む図面があれば1点
3. 容量の大きい図面（10MB以上など）1点（実機の時間・メモリ測定用）
4. 作成元CAD（AutoCAD / AutoCAD LT / Jw_cad経由 / その他）とバージョン

変換結果（DXFと `report.json`）をお返しし、AutoCAD等での開き直し・比較をお願いする流れを想定しています。

## 8. iPhone/iPad Safari 実機検証の進め方

`web/` を HTTPS で配信する必要があります（Service Workerは HTTPS か localhost でのみ動作）。候補:
- GitHub Pages / Cloudflare Pages 等の静的ホスティング（公開URLになる＝GPL上の「配布」）
- 一時的な検証なら、開発PCのサーバーを Cloudflare Tunnel 等でHTTPS公開する方法もある（URLを知る人はアクセス可能）

実機チェックリスト:
1. Safariで開き「オフライン利用可能」表示を確認 → 共有メニューから「ホーム画面に追加」
2. 機内モードにしてホーム画面から起動 → ファイルアプリのDWGを選択 → 変換 → 「DXFを保存」「共有…」
3. 変換時間（画面に表示）とWASMメモリ表示を記録。大きいファイルでタブが落ちないか
4. Safariの「履歴とWebサイトデータを消去」後にオフライン起動できないこと（＝再度オンラインで読み込みが必要）を確認
5. 注意: Safari（ホーム画面に追加していないサイト）は、長期間（7日程度）使わないとキャッシュが消える場合がある。ホーム画面アプリを推奨

## 9. ライセンス（GPLv3）の整理 ※法的助言ではありません

- **個人利用**（自分の端末で使うだけ）: 改変・利用に制約はほぼない。
- **他人への配布**: Webで公開する場合も、JS/WASMは利用者の端末へ送られ実行されるため「頒布」に当たると考えるのが安全。GPLv3の全文と対応ソース（LibreDWG＋パッチ＋本アプリ）を入手可能にする必要がある（`web/SOURCE.txt` に雛形）。
- **既存アプリ（非公開・独自ライセンス）への組み込み**: 同一プログラムとして結合すると、全体をGPL互換で頒布する必要が生じうる。別プロセス扱いで回避できるかは個別判断が必要で、**専門家への確認を推奨**。
- **iOS App Store**: GPLv3とApp Storeの利用条件は両立しないとする見解（FSF）があり、LibreDWGを同梱したiOSアプリ方式は配布形態に注意が必要。

## 10. 代替候補（ODA）について

ODAは Drawings SDK をWebAssembly化した「Drawings inWEB SDK」を提供しており、追加インストールや第三者サービスへの接続なしで動作するとしています。ただし利用はODA会員に限られ、会員契約が必要です（60日の試用あり）。価格、DXF書出をブラウザ内で行えるか、Safari対応、オフライン条件は公開情報では確認できず、問い合わせが必要です。
